## 1. Objective and architecture

Evaluate goal-directed navigation with 32 synchronous DeepMind Lab environments, a Vision module, a Grid Network and A2C Actor-Critic. The Actor consumes the **learned 512D Grid bottleneck**, first-hit goal memory (remembered 512D grid code), previous action and reward; it is **not** fed oracle PC/HD features. Ground-truth position and heading still provide auxiliary supervised PC/HD targets for Vision/Grid. Thus this is **not** fully oracle-free training.

Arena 2.5m × 2.5m; 5,400 engine frames = 90 simulated seconds = 1,350 actions per episode, action repeat 4. At the first goal arrival the goal-memory code is acquired; after a hit the agent teleports to search for the **same** goal again within the episode. Sparse visual cues ~5% by design. Grid 512D, recurrent hidden state 128D; Actor recurrent hidden 256D. Actor A2C learning does not directly backpropagate its loss through Grid/Vision under the recorded implementation.

Paired goals/episode difference = **+4.980** (+69.5%); episode-bootstrap 95% CI **[3.300, 6.620]**. Paired episode comparisons: 68 better, 11 tied, 21 worse in 169M. This is a single training history; a bootstrap over evaluation episodes does NOT quantify across-training-seed uncertainty.

**Critical distinction:** `first-hit success 85%` means at least one goal within **90 s**, *not* first hit within 10 seconds. The **10-second 92.4% is only post-first-hit teleport return success**, with right-censored attempts excluded. Need measure **first hit within 10 s** separately.

**Critical caveats:** Return attempts from the same episode are correlated; estimate uncertainty by episode/block resampling, not independent-attempt binomial assumptions. Successful-only mean first-hit actions may not reflect the full first-hit distribution. Goal debug Y-axis sign was corrected offline in this evaluator (sign -1, median corrected hit distance 0.126m); heading calibration reported sign +1, 0 deg offset. Do not silently modify the training policy/goal code based on postprocessing.

## 5. Next experiments at approximately 269M

1. **Finalize and freeze:** wait for completed 268,992,000-frame checkpoint (or record actual safe-stop count), create a distinct immutable `latest_backup_269m.pt`, preserve its replay and optimizers. Do not evaluate an actively changing `latest.pt`.
2. **Matched behavioral eval:** 80M, 169M, 269M, each 100 or preferably more episodes with same seeds and environment/action-repeat/goal-memory/vision-rate settings. Report goals/episode, paired episode bootstrap CIs, first hit probability within 90s, first-hit distribution with non-hit censoring, and **first hit within 10 s** (from episode spawn).
3. **Post-teleport returns:** separately report **within 10 seconds of teleport**, 20 and 40-second horizons, eligible attempts, successes, censored attempts, episode-clustered confidence intervals. Avoid pooling return attempts as independent experiments.
4. **Five representative trajectories**, selected by **predefined objective strata** instead of cherry-picking five successes: (i) median successful return, (ii) efficient/direct return, (iii) meandering successful return, (iv) no first hit, (v) first-hit success with poor/late revisit. For unavailable strata, state this explicitly. Match episode seeds across all three checkpoints; plot same arena axes, corrected debug goal, exploration (before first hit) vs goal-known phase, teleport points and chronological arrows, up to five returns where present. Annotate first-hit actions, revisit actions, initial goal distance, traveled path length, and efficiency `straight-line distance / actual path distance`. Segment trajectories at teleports rather than connecting them with artificial long paths.
5. **Gridness and pattern stability:** compare 80/169/269M with shared-trajectory controls and same rate-map/SAC/scorer. Count `>0.37` descriptively, include min-max and mean metrics, top-32 maps, per-bin occupancy, split-half correlation and shuffle-based null tests. Navigation performance alone cannot establish hexagonal grid cells.
6. **Goal-memory ablation:** paired goal-memory ON/OFF and possibly wrong-goal memory after first hit; matched start and teleport initializations. Improved return rates alone do **not** prove vector-based navigation; combine behavioral, path-efficiency and causal ablation evidence.
